# Daily engineering workflow

Give Kelechi Mode one outcome, the relevant repository or issue, acceptance criteria and the action boundaries. The host keeps the task moving and reconciles every named deliverable before handoff.

| Need | Entry point | Evidence to expect |
| --- | --- | --- |
| Investigate a support issue | `kelechi-mode`: investigate this ticket | Current symptom, ranked hypotheses, production evidence within authorized access, verdict and a draft update |
| Choose between approaches | `research` | A decision record with criteria, current-source facts, alternatives including no change, a discriminating probe and limits |
| Explore UI directions | `create-canvas` | Named live variants in the existing showcase, synthetic fixtures, a typed registry and a preserved baseline |
| Check a UI feature | `ui-sweep` | A state inventory, actual inspected PNGs, interaction checks, critique and explicit missing boundaries |
| Capture recurring obstacles | `friction-log` | Stable entries with expected/actual results, attempts, resolution, evidence and a specific follow-up |
| Deliver repeated bounded work | `software-factory` | An event claim, actual check receipts, independent review, current-source readiness and a reviewable result |

For a support task, reproduce the failing employee/date/surface before fixing it. When the current example works, preserve that result and request the exact failing example. A proven general mechanism does not establish the customer's cause. Keep company evidence in the company's private workspace.

For a UI task, preserve the baseline and compare distinct concepts with the same fixture and dimensions. Inspect loading, empty, error and permission states where reachable. A component story can prove that component; workflow, authentication and document integration need their own checks. A requested freeform canvas additionally follows the workspace contract; a comparison story does not prove pan/zoom.

For a code change, use the repository's narrow checks and real consumer boundary. Give a fresh reviewer the requirement, relevant producers and consumers, and scope limits. Verify concrete findings. Reconcile every user-requested result to its artifact, rather than treating tooling prerequisites as completion.

For repeatable delivery, follow [the existing task commands](delivery.md). Start manually with one event and one writer. The collector does not receive Linear/webhook events, schedule agents, enforce model spend, approve changes or deploy. Add event intake only after a task has worked and the trigger, cadence and authority are agreed. Readiness is permission to review the evidence.

Track user corrections separately from normal product decisions and access approvals. Record actual wall-clock intervals, tokens or cost only when the host supplies them. Compare repeated outcomes and escaped defects before widening autonomy; a small replay or green command cannot establish a shipping-safety rate.

## Adaptation choices

| Source | Retained | Local adaptation |
| --- | --- | --- |
| [research](https://pqoqubbw.dev/skills/research) | Project grounding, alternatives, falsification and measurements | Host-native orchestration and explicit bounds replace fixed fan-out; research does not authorize implementation |
| [create-canvas](https://github.com/ibelick/ui-skills/blob/main/skills/create-canvas/SKILL.md) | Named live variants, stable source registry, interaction and camera requirements | Reuse Storybook first; implement the full freeform contract only when requested |
| [ui-sweep](https://github.com/ref-tools/marketplace/blob/main/plugins/ref-skills/skills/ui-sweep/SKILL.md) | State inventory, inspected captures, interaction evidence and critique | Local catalogs replace required service upload/publication; private fixtures stay local |
| [friction-log](https://github.com/aurorascharff/agent-friction-skill/blob/main/SKILL.md) | Progressive failures, attempts, resolutions and concrete actions | Minimal task-local evidence replaces default full-conversation capture; configuration changes remain separately authorized |
