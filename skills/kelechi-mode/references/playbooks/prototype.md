# Prototype

A throwaway sketch that settles a decision by observation instead of opinion.

1. Write the question the prototype answers and what result would decide it, before building anything.
2. Build the smallest thing that makes the difference observable: a script, a scratch route, a component in isolation, a query against local data. Two or three competing variants when the design space is genuinely open.
3. Keep it out of production code: a scratch directory, a throwaway branch, or `.kelechi/`.
4. Run each variant and record what you observed, measured where measurable.
5. Decide, or show the user the observed difference when the call is a genuine product preference.
6. Delete the prototype. Carry forward only the decision and the evidence behind it.
