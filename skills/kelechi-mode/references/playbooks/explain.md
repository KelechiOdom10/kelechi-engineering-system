# Explain

1. Decide which explanation is needed: `how` is current behaviour, `why` may need history, `teach` usually needs both.
2. Read the smallest set of authoritative current sources. Use history to explain intent, never as proof of present behaviour.
3. Build a concrete mental model from entry point through the important state transitions to outputs. A diagram helps when there are more than three moving parts.
4. Separate verified facts from inference and link claims to files.
5. Lead with the answer at the reader's altitude, in plain words. Leave the code unchanged unless separately asked.
